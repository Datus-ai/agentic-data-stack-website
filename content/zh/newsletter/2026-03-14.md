## 重点动态

### MCP 在数据工具中的应用

Model Context Protocol 正成为连接 AI Agent 与数据工具的重要接口。本期英文原稿记录了多个平台增加 MCP 支持的趋势。

- 来源：[modelcontextprotocol.io](https://modelcontextprotocol.io)
- 意义：MCP 统一工具发现、查询与操作方式，减少定制集成代码，提高 Data Agent 的可移植性。

### Apache Iceberg：Agent 的表格式与目录接口

Iceberg 的 REST Catalog 规范提供 HTTP 接口，让 Agent 能够发现 Schema、使用时间旅行，并管理表结构演进。

- 来源：[iceberg.apache.org](https://iceberg.apache.org)
- 意义：Agent 需要程序化、无状态的目录访问方式，REST 接口适合这一使用模式。

## 工具与发布

### DuckDB 的程序化接口与扩展

本期原稿讨论 DuckDB 1.2 的程序化接口和扩展框架，以及嵌入式 SQL 引擎在 Agent 本地数据处理中的用途。

### Unity Catalog 的多引擎方向

本期关注开源 Unity Catalog 与多个查询引擎结合的方向，以及统一治理在多引擎 Agent 架构中的作用。

## 值得阅读

### 为什么 Data Agent 需要语义层

不了解业务上下文而直接查询原始表，可能产生不可靠答案。Cube、dbt Semantic Layer 等语义层提供业务逻辑与指标定义，让 Agent 超越单纯 SQL 生成。

### 数据团队的 Agent-readiness 检查

检查目录是否可访问、工具是否可被程序化操作，以及 Agent 是否理解业务语义，是评估现有技术栈的重要起点。
